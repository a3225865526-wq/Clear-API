# API Key、Base URL 与模型

## 创建第一把 Key

1. 登录后打开[API 密钥](/keys)，点击“创建 API 密钥”。
2. 填写易识别的名称，例如“家用电脑聊天”；不同工具分别建 Key，便于查消费和单独停用。
3. 从页面实际提供的分组中选择。不了解分组时先保留站点默认值，再核对目标模型是否属于该分组；`auto` 的顺序会影响路由选择，不要照抄其他人的配置。
4. 按需要设置有效期。建议第一次只创建 1 把 Key，先设置适合测试的小额度；额度单位以表单标签为准。
5. 如开启“无限额度”，它仅取消这把 Key 自身的额度限制，不会增加账户余额，也不代表免费调用。账户余额与 Key 剩余额度均需满足请求要求。
6. 模型限制和 IP 白名单只在明确需要时填写；模型限制需包含目标模型，IP 白名单填实际出口 IP，不能填本机内网 IP 来代替。
7. 点击“保存更改”。在列表对应行的操作菜单中选择“复制密钥”，按页面要求完成安全验证后，将完整 Key 填入自己的客户端。

列表中的掩码不是完整 Key。不要手动删掉或重复添加 `sk-` 前缀，直接使用“复制密钥”的结果。密码、邮箱验证码、充值卡密和安全页面的个人访问令牌都不能代替用于模型调用的 API Key。

## 管理与保护

保存到可信客户端或当前终端的环境变量，不要放入网页前端、公开仓库、截图、日志或安装包。不再使用时从该 Key 的操作菜单停用或删除。疑似泄露时立即停用，创建新 Key，更新客户端并核对[使用日志](/usage-logs/common)。

## Base URL 怎么填

Relay 请求使用 `Authorization: Bearer <API_KEY>`。当前实现也保留 Gemini 兼容认证 `x-goog-api-key` 或 `?key=`，但公开示例优先使用 Bearer，避免 Key 暴露在 URL。

在密钥页点击“API 地址”复制服务地址，不凭网站登录域名猜测 API 域名。OpenAI 兼容客户端一般填写“服务地址 + `/v1`”；如果复制的地址已有 `/v1`，不要再追加。客户端自己追加 `/v1` 时只填根地址。Base URL 不填写 `/chat/completions`，除非该字段明确要求完整请求 URL。

## 选择模型

打开[模型广场](/pricing)，搜索模型并查看协议、分组、价格和限制。再带上准备使用的 Key 调用 `GET /v1/models`，复制返回的完整 `data[].id`，包括大小写和版本后缀。列表按当前 Key 权限生成；换 Key、分组或模型限制后需要重新查询。不要将展示名称、渠道名或客户端预设名称当作模型 ID。

模型能否调用取决于账号、Key、分组、额度及当前服务配置。普通用户请求不需要发送分组或渠道编号。没有可用模型时先核对这些条件，不要随机猜名称。

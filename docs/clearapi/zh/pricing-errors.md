# 模型价格、消费记录与常见错误

## 调用前查看价格

1. 打开[模型广场](/pricing)，搜索准备调用的完整模型 ID。
2. 核对可用分组、协议、计费方式、币种和单位。模型同名也可能因分组及配置不同产生不同消耗。
3. 文本按 token 计费时，分别看输入、输出，以及适用的缓存价格；“每百万 token”不能当作“每次请求”的价格。图片、视频和按次模型按页面显示的实际单位理解。
4. 先用小输出上限和短文本测试，再放开长对话或批量调用。聊天记录越长、输出越多，消耗可能越大；客户端也可能发出额外请求。

本页不写固定价格、汇率或折扣。充值人民币金额、平台 API 额度、Key 额度和 token 数量含义不同，不要直接按同一个数字比较。价格和额度以当前页面与调用记录为准；最终消耗需结合实际用量及适用计费规则核对。

## 查看消费记录

1. 登录后打开[使用日志](/usage-logs/common)，按请求时间、模型及 API Key 名称定位刚才的请求，调整筛选后点击搜索。
2. 核对时间、模型、Key、分组、输入输出 token 和消耗；展开记录查看页面提供的详情。图片或异步任务可到[任务日志](/usage-logs/task)核对状态及结果。
3. 到[钱包](/wallet)查看当前余额及累计消耗。余额下的“余额明细”用于核对充值、赠送及其他余额调整，不是逐条 API 消费清单；逐次调用请看使用日志。
4. 有并发请求时要按同一时间段核对多条记录，不能用一条请求的消耗解释整个余额差额。页面未更新时先刷新，仍不一致再保留时间范围和记录信息联系支持。

## 常见错误

以下是排查方向，状态码不是唯一依据；同一类错误可能由不同上游返回。优先阅读响应中的 `error.message`、`error.code` 或站点显示的具体提示。

| 提示或现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 400 / 参数错误 | JSON、Content-Type、模型支持的字段 | 使用最小文本请求；若提示需输出上限，填写模型支持的 `max_tokens` 或 `max_completion_tokens`，不要同时发送冲突值 |
| 401 / Key 无效或过期 | 是否粘贴完整 API Key，是否停用或过期 | 在密钥页重新复制；泄露的 Key 停用后重建 |
| 403 / 无权限 | Key 分组、模型限制、IP 白名单、账号状态 | 核对当前 Key 的权限，不能靠换客户端绕过限制 |
| 404 / 找不到资源 | API 地址、重复 `/v1`、模型 ID、接口协议 | 重新查询 `/v1/models`，按模型支持的接口调用 |
| 429 / 限流 | 请求频率、并发数、具体错误说明 | 降低并发并稍后重试；不要持续自动重发 |
| 余额不足 / Key 额度不足 | 钱包余额、Key 额度、输出预算 | 充值或合理调整自己的 Key 额度，降低请求预算；无限 Key 额度不会增加余额 |
| 5xx / 无可用渠道 / 上游错误 | 模型当前状态和请求编号 | 保存错误后稍后重试；避免同时更改多个配置 |
| 返回 HTML 网页 | 是否请求了网站页面、代理是否改写路径 | 使用 API 地址和正确接口路径 |
| 超时或没有回复 | 网络、客户端协议、流式支持及使用日志 | 先查是否已有完成记录，再决定重试，避免重复请求产生额外消耗 |

Anthropic 形式错误通常有外层 `type: error` 与 `error` 字段；其他接口常使用 `error` 对象。不能把模型列表返回成功等同于生成请求一定成功。

## 充值和注册问题

- 已付款但没余额：到商城取卡密，回钱包按[充值与兑换](quickstart.md#充值与兑换)完成兑换；付款不会自动到账。
- 兑换失败：核对码类型、完整性、当前账号和余额明细。先确认到账结果，不要反复试不同入口或重复购买。
- 没有充值商品或目标模型：当前配置可能未开放，通过站点公布的支持渠道咨询，不保证何时恢复。
- 验证码收不到：检查邮箱和垃圾邮件，等待倒计时结束再发；人机验证未通过时先完成验证。
- 客户端失败：先按[客户端接入](clients.md)用同一 Key 做最小请求，区分地址、权限与客户端问题。

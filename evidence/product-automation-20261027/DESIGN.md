## 已确认目标

将现有商品的“提交审核 → 人工审核 → 发布”改为 Root 发起一次“保存并启用”，后端自动准备内部证据、校验并发布。兑换码改为选择商品和数量后一次“生成并下载”。不包含后台自动补货、自动上传云猫、自动付款或第三方订单对接。

## 商品页面

- 默认显示商品摘要：名称、人民币售价、API Quota、状态；按需展开编辑。
- 日常填写名称、售价、API Quota、购买链接。新商品自动产生稳定的产品标识，从受信任的购买链接解析交付绑定；后端仍验证合法性与唯一性，不猜测价格或 Quota。
- 描述、排序、技术标识、证据与旧商品映射进入高级设置或历史详情。自动证据关联不要求手填批次 ID。
- 保留“保存草稿”，明确的“保存并启用”才触发自动发布。不能因加载页面、部署、普通保存或批次导出而发布商品。
- 已发布商品显示“生成兑换码”；归档、下架、撤销和删除进入更多操作。复用项目现有列表、折叠、确认与安全验证组件。

## 自动启用的后端契约

1. 仅 Root 活跃管理会话可以执行；同时核查编辑、审核和发布权限。使用绑定商品、修订、目录版本、输入契约及动作的现有安全验证机制，合并业务操作，不绕过认证或重放保护。
2. 后端校验人民币售价、整数 Quota、受信任购买地址、交付绑定、归档/撤销状态和并发版本。价格与 Quota 各自来自明确配置，不新增换算规则。
3. 现有有效样码直接复用。首次缺少样码且满足现有安全签发条件时，自动生成一枚真实内部样码并关联系统分配的批次 ID。不得复制签发记录、伪造 ID 或恢复历史禁用证据。
4. 已有证据禁用、过期、撤销或商品/修订/绑定不匹配时拒绝，并说明原因；不通过替换证据来掩盖这些异常。关键契约变更产生新修订，原证据与历史记录完整保留，新修订重新准备和校验自身证据。
5. 校验成功后记录可区分的“系统自动校验”政策和审计事件，再发布。不得把自动动作伪装成旧的人工审批；旧人工审批和撤销仍有效。
6. 内部样码生成、自动校验审计及发布状态在同一数据库事务内完成；任一步失败不留下部分启用结果。若保存草稿与启用采用先后两个请求，启用失败必须清楚提示“草稿已保存，未发布”，允许安全恢复。
7. 同一输入重复提交不得重复生成样码、审批或发布事件；目录锁和版本校验阻止旧页面覆盖新版本。没有通过自动校验的商品不能发行正式批次。
8. 内部一致性校验不等于第三方真实交付成功。界面和报告必须区分这两者；不会自动生成真实订单、付款或把未实测的云猫交付标记为测试通过。

## 一键生成并下载

- 每次明确选择已启用且证据有效的商品、输入数量。保留现有每批 1–100 的数量限制；有效期可选，留空继续表示永久。
- 系统自动提供批次名称和商品修订、证据/自动校验关联、售价与冻结 Quota，名称可以在高级设置中调整。
- 单次提交创建批次和所有兑换码，成功后直接下载 TXT；可保留 CSV 选择和现有批次列表的重新导出入口。
- 失败整体回滚；创建成功而下载失败时，只重新下载同一批次，不再次发码。重复点击、网络重试使用稳定批次请求身份并在后端锁内防重，不只禁用前端按钮。
- 同一有效修订可以反复生成不同批次，面额与 Quota 不变；名称、数量和有效期独立。
- 下载失败和服务端失败区分提示。兑换码仅通过管理员授权下载，不写日志、审计或本地持久缓存。

## 改动范围

优先修改既有 model/credit_approval.go、model/redemption_batch.go、相应 controller/router、商品编辑与操作组件、批次创建/下载组件及现有定向测试和翻译。复用现有模型、目录 JSON、审批审计表和事务；优先不增加 SQL schema 或迁移。

不修改支付、定价、用户余额、兑换结算、Gateway/Executor、邀请奖励、PG03 或 D 生图。保留归档与删除的后端关联检查，不删除任何历史记录。

## 必要验证

- 自动启用：有效证据通过；首次样码签发正确；人工与自动审计明确区分；旧审批兼容；无效、禁用、过期、撤销、不匹配证据仍拒绝。
- 安全：匿名、普通用户、普通管理员、仅 Root token、缺少或过期/错绑/重复使用安全凭证不能越权启用；旧目录版本和归档/撤销状态不能被静默覆盖。
- 一致性：样码/审计/发布失败回滚；重试不重复发布或发码；不同批次复用有效修订；下载失败只重下原批次。
- 使用现有真实 SQLite、MySQL、PostgreSQL 隔离测试体系验证受影响持久化行为，记录实际版本、命令和结果；若需要 schema 变更，另行报告迁移与授权要求。
- 前端定向验证商品简化表单、自动启用状态、生成并下载、失败重试与原归档/删除操作；类型检查、变更文件 lint/格式检查与七语言翻译。
- 不为本轮重复运行无关全量测试，不制造真实付款或生产测试库存。

## 部署与现有生产数据

通过必要检查后沿用 Windows 本地构建 → SSH → VPS helper；核对真实生产前驱、备份、产物身份、回退条件及健康，不切换发布系统。

本次功能授权不自动处理当前 credit-1@5，不自动发布任何既有草稿/待审核商品，也不自动创建正式库存；只有用户之后主动点击新入口才执行相应业务操作。现有真实交付测试与本次代码部署分别记录，不能把部署成功写成第三方交付或库存验收成功。
